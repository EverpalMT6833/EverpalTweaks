2. ROOT CAUSE ANALYSIS: THE PACKAGING & RUNTIME PITFALLS
================================================================================

2.1. The Fatal ABI Path Packaging Bug (lib/arm64 vs lib/arm64-v8a)
------------------------------------------------------------------
In raw APK dumps, `libcamera_algoup_jni.xiaomi.so` was placed under `lib/arm64/`.
On Android, the 64-bit ARM ABI directory name is strictly `arm64-v8a`.
Directories named `arm64` are completely ignored by PackageManager.
When `MiCamAlgoInterfaceJNI` attempted `System.loadLibrary("camera_algoup_jni.xiaomi")`,
Android threw `UnsatisfiedLinkError` and crashed the app on startup.

Fix: Relocated `libcamera_algoup_jni.xiaomi.so` to `lib/arm64-v8a/` inside the APK,
ensuring Android's ClassLoader can resolve and link it.

2.2. Stub Signature Stripping & Multi-Scheme (v1/v2/v3) Verification
--------------------------------------------------------------------
The original APK was signed only under v3 with a placeholder certificate
`CN=Weather Stub`. This caused signature collisions and installation rejections
(`INSTALL_FAILED_UPDATE_INCOMPATIBLE`).

Fix: Stripped old `META-INF/` signature entries, performed 4-byte/16KB page alignment
via `zipalign -p -f 4`, and signed using `apksigner` with a dedicated `CN=MiuiCamera`
certificate supporting v1, v2, and v3 signature schemes.

2.3. Missing JNI Algorithm Stub Breakdown (algoup_stub.c symbols)
-----------------------------------------------------------------
To decouple Leica Camera from missing MIUI daemons on pure AOSP, the bundled
`libcamera_algoup_jni.xiaomi.so` stubs out all required native methods:
- Java_com_xiaomi_engine_MiCamAlgoInterfaceJNI_init
- Java_com_xiaomi_engine_MiCamAlgoInterfaceJNI_deInit
- Java_com_xiaomi_engine_MiCamAlgoInterfaceJNI_getVersionCode
- Java_com_xiaomi_engine_MiCamAlgoInterfaceJNI_setMiViInfo
- Java_com_xiaomi_engine_MiCamAlgoInterfaceJNI_createSessionByOutputConfigurations
- Java_com_xiaomi_engine_MiCamAlgoInterfaceJNI_createSessionWithSurfaces
- Java_com_xiaomi_engine_MiCamAlgoInterfaceJNI_destroySession
- Java_com_xiaomi_engine_MiCamAlgoInterfaceJNI_flush
- Java_com_xiaomi_engine_MiCamAlgoInterfaceJNI_preProcess
- Java_com_xiaomi_engine_MiCamAlgoInterfaceJNI_processFrame
- Java_com_xiaomi_engine_MiCamAlgoInterfaceJNI_processFrameWithSync
- Java_com_xiaomi_engine_MiCamAlgoInterfaceJNI_quickFinish
- Java_com_xiaomi_engine_MiCamAlgoInterfaceJNI_dumpGcov

2.4. Elimination of 5-Second Mode Changing Delay (replaceSessionClose()V)
-------------------------------------------------------------------------
Xiaomi added a proprietary `replaceSessionClose()V` method to CameraCaptureSessionImpl
in HyperOS. Calling it on AOSP 16 threw `NoSuchMethodError`, stalling handler thread
`ch.b` until the 5,000ms CameraService abort timeout expired.
Fix: Diverted calls to `CameraCaptureSession.close()V` in `dh/e.smali` and
`MockCameraImageReceiver.smali`, achieving instant (<200ms) transitions.

2.5. Capture Result Reflection & Dalvik Register Verification Fix
-----------------------------------------------------------------
HyperOS camera depends on `ICustomCaptureResult` for frame completion. On AOSP,
reflection on `CaptureRequest.getNativeCopy()` failed, causing NPE in `ba.p1` on
`getTimeStamp()`. Furthermore, register allocation clobbered `p0`, triggering an
ART `VerifyError: Verifier rejected class xf.a`.
Fix: Re-implemented `xf.a` using `.locals 8`, guarded null branching in `ba.p1` and
`o$b`, and provided fallback to `getNativeMetadata()`.

2.6. MT6833 Snapshot Burst Memory Protection & LMKD Tuning
----------------------------------------------------------
Snapshot burst allocation (12.5 MP YUV420 buffers via `initMfnrCore`) spiked memory
usage, causing Zone Normal (~374 MB managed) watermark breaches. Android 16 LMKD
default `ro.lmk.pressure_after_kill_min_score=0` resulted in foreground camera kills.
Fix: Armed `ro.lmk.pressure_after_kill_min_score=201`, `ro.lmk.lowmem_min_oom_score=201`,
and tuned `vm.lowmem_reserve_ratio="256 256"` (freeing 4,048 pages for Zone Normal).
